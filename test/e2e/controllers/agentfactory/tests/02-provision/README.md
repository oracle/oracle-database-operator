# Agent Factory test02

Test02 validates the TCPS wallet path against SIDB test02. It waits for SIDB
TCPS, copies the SIDB client wallet from the database Pod, patches the wallet
into the runtime Secret, and applies the Wallet connection manifest. The
controller then creates the `paf-db-setup` Job, which connects through the
wallet using the temporary administrator Secret, creates or upgrades `paf_user`
and `AAI_RO_paf_user`, and validates the grants and quota.

The preparation hook makes the wallet portable before packaging it. SIDB can
write `MY_WALLET_DIRECTORY` as an absolute path that exists only inside the
SIDB Pod; that override is removed from the single-wallet archive, and the
controller setup Job also relocates the entry if it is present in a
user-provided archive. The hook also rewrites `tnsnames.ora` `HOST` to the
SIDB Service FQDN and sets `sqlnet.ora` `WALLET_LOCATION` `DIRECTORY` to `.`
so the wallet opens outside the SIDB Pod. During wallet extraction, the Job
rewrites the `sqlnet.ora` wallet `DIRECTORY` again to the Job's temporary
extraction path, so TCPS does not depend on a path from the SIDB Pod or on a
fixed `/tmp` directory.

If SIDB does not report TCPS enabled, the preparation hook records the
password-mode fallback and continues with the Details/password flow. For the
wallet path, the administrator Secret remains available until the controller
Job succeeds. With the default `DeleteOnSuccess` policy, the controller
deletes that Secret after successful setup.

## Run

Use the ordered dependency sequence:

~~~
E2E_TESTS=sidb/test02,agentfactory/test02
~~~

agentfactory/test02 alone requires an already-ready SIDB resource and wallet
or AGENTFACTORY_REQUIRES_SIDB=false plus equivalent database inputs.

The test starts with fresh runtime and administrator Secrets. Before the
AgentFactory CR is applied, `prepare-database.sh` reads
`spec.security.secrets.admin.secretName` and `secretKey` from the dependent SIDB
CR and synchronizes the referenced password into the test02 bootstrap Secret.
The SIDB Secret is not modified, and the password is not placed in diagnostics.
This is an E2E-only dependency flow; customers still provide the administrator
Secret directly through the AgentFactory resource. When wallet
preparation succeeds it switches to test02-wallet.yaml, sets
database.connectionType to Wallet, and leaves bootstrap enabled. The
controller creates the setup ConfigMap and Job; the Job performs the idempotent
PAF user/grant setup before the AgentFactory workload starts.

## Security and diagnostics

The bootstrap Secret is deleted after the controller Job succeeds when using
`DeleteOnSuccess`. The diagnostics archive contains the generated Secret
metadata, wallet package, and command trace; restrict access to the archive
and remove it after troubleshooting.
